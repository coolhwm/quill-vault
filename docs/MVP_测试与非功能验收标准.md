# Quillvault MVP 测试与非功能验收标准

> 状态：已确认，实施中
> 日期：2026-07-30
> 发布目标：TestFlight 内测

## 1. 质量原则

优先级固定为：

1. 不丢录音；
2. 不损坏 Markdown 资产；
3. 已就绪逐字稿始终可以生成纪要；
4. 状态和恢复行为可解释；
5. App 不成为 AI 性能瓶颈；
6. UI 可用、美观且可访问。

任何录音或会议资产不可逆损坏问题都是发布阻断项，不能以发生概率低为理由降级。

## 2. 测试层级

| 层级 | 目标 | 工具 |
| --- | --- | --- |
| Domain | 状态机、不变量、错误分类、进度 | Swift Testing |
| Application | 用例编排、幂等、恢复、取消 | Swift Testing + Test Doubles |
| Adapter Integration | GRDB、文件、HTTP、SSE、Keychain 映射 | Swift Testing/XCTest |
| UI Component | 关键状态、布局、动态字体 | SnapshotTesting |
| UI Flow | 首页、录音、生成、搜索、配置 | XCUITest |
| System | BackgroundTasks、Speech、Audio、App Intents | 真机 |
| End-to-End | 真实会议资产与真实 BYOK | 真机 + 人工核验 |

核心正确性不得只由 UI 自动化或人工测试覆盖。

## 3. 自动化测试要求

### 3.1 Domain

必须覆盖所有合法和非法状态转换：

- recording → interrupted → recording；
- recording/interrupted → finalizingTranscript；
- finalizingTranscript → pendingMinutes；
- pendingMinutes → generatingMinutes；
- generatingMinutes ↔ generationPaused；
- generatingMinutes → minutesCompleted；
- minutesCompleted → minutesStale；
- stale/completed/pending → 新一代 generating。

不变量：

- 同一时刻最多一个活跃录音；
- 同一会议最多一个活跃生成 Job；
- 已完成 Step 不因恢复重复计费；
- 进度不倒退；
- 发布前不显示 100%；
- 未验证逐字稿不得进入生成；
- 新纪要发布前旧纪要可读；
- 任何 AttemptFailure 不删除录音或逐字稿；
- 当前模型变化不改变旧 Job 快照。

使用参数化测试覆盖错误类型、任务状态、外部文件状态和模型配置状态的组合。

### 3.2 Generation Pipeline

必须覆盖：

- 0、1、多个和超长逐字稿分段；
- 分块边界稳定；
- Prompt/Schema/ChunkPlan 版本进入幂等键；
- 每个 Step 前、中、后取消；
- 每个 Step 完成后进程终止并恢复；
- 408、429、500、502、503、超时和连接重置；
- `Retry-After`；
- 401/403、模型不存在和请求过大；
- 流式与非流式响应；
- SSE 分片落在任意字节边界；
- UTF-8 多字节字符被拆包；
- Provider 缺失可选字段；
- 合法 JSON、Markdown fenced JSON、前后噪声；
- 缺少次要字段、图节点或边；
- 空响应、垃圾内容和不可恢复结构；
- 输出宽容发布与“不完整”提示；
- 外部修改逐字稿导致纪要过期；
- 外部修改旧纪要后的替换确认；
- 手动继续与重新生成世代隔离。

所有网络测试使用本地 Stub Server 或 URLProtocol，不消耗真实模型费用。

### 3.3 Persistence

- 所有 GRDB migration 从每个历史 schema 升级到最新；
- migration 可重复启动，失败后不留下半迁移状态；
- Job 与 Step 使用事务一致更新；
- WAL 并发读写；
- FTS 插入、更新、删除与重建；
- 2,000 场索引重建；
- 数据库文件删除后重建；
- 数据库损坏时隔离旧库并重建，不触碰会议文件；
- 重建后 Meeting ID、状态与文件关联稳定；
- 诊断表按时间和容量循环淘汰。

### 3.4 File Store

在临时目录和可控故障 FileSystem 中覆盖：

- 创建会议资产目录；
- 同目录临时写入与原子替换；
- 写入前、写入中、replace 前和 replace 后故障；
- 磁盘空间不足；
- 无权限、书签失效和文件被移动；
- iCloud item 尚未下载；
- 外部同时修改 `transcript.md`；
- 外部同时修改 `minutes.md`；
- 候选纪要清理；
- 不完整临时文件不被索引；
- `minutes.md` 失败时保留旧版本；
- 音频与逐字稿永不因纪要失败删除。

### 3.5 AI Client

- Base URL 规范化和路径拼接；
- 只允许 HTTPS；明确开发模式除外；
- Authorization Header 不进入日志；
- 请求不包含音频、文件 URL 或非必要元数据；
- OpenAI-compatible 宽容 DTO；
- 状态码、网络错误和取消映射；
- URLSession metrics 完整采集；
- 请求/响应大小统计；
- 首字节时间；
- Provider usage token；
- SSE 结束标记；
- 重试由 Generation Runtime 控制，Client 不私自无限重连。

### 3.6 UI

关键快照至少包含：

- 首页空状态、最近会议、生成中、中断会议；
- 录音 0 秒、长时长、转写中、音频中断；
- 会议列表 0/1/大量结果；
- 搜索与筛选；
- 详情的总结、图示、逐字稿、播放器；
- 待生成、生成中、暂停、完成、过期；
- 模型列表、编辑、测试失败和密钥已保存；
- 目录权限失效；
- 不完整纪要提示。

矩阵：

- Light/Dark；
- 默认字体与最大 Accessibility Dynamic Type；
- iPhone 小屏与主流屏幕；
- 中文与英语；
- Reduce Motion；
- 长标题、长模型名、长错误信息。

XCUITest 覆盖三个一级入口、录音主流程、模型配置、重新生成、搜索和诊断导出。

## 4. 真机可靠性门槛

### 4.1 设备

TestFlight 前至少在两台运行 iOS 26 的物理 iPhone 验证：

- 一台支持 Action Button；
- 一台不同屏幕尺寸或硬件代际；
- 至少一台使用真实 iCloud/Obsidian 权威目录。

### 4.2 录音

| 场景 | 通过标准 |
| --- | --- |
| 3 小时连续会议 | 音频可播放，时长与墙钟误差 ≤ 1%，无已知有人声丢失 |
| 锁屏/后台 ≥ 2 小时 | 录音持续，前台恢复后状态正确 |
| 10 场/8 小时日负载 | 全部会议可结束并产生可解析音频 |
| 来电/系统中断 | 明确标记缺口，条件允许时恢复 |
| 路由插拔 | 不崩溃、不静默写 0 秒文件 |
| 强制终止 | 重启后发现中断会议，既有录音可播放 |
| 低存储 | 录音前/中提示，已写内容可恢复 |
| 麦克风拒绝 | 不创建伪会议或空资产 |

核验不只比较文件大小；必须检查容器时长、音频包、时间轴并抽听关键区段。

### 4.3 转写

- 3 小时录音最终可以完成转写；
- 最终时间轴单调，无重复 final segment；
- 后台暂停分析后可以从录音追平；
- 已有人声区段不存在已知字幕空洞；
- 无人声区段允许没有字幕；
- 逐字稿写入失败时会议不进入“待生成纪要”；
- 冷启动后可以继续未完成的 finalization；
- 中文为完整 QA 语言，英语完成核心回归。

### 4.4 Action Button

- 已授权且资源就绪时，从触发到音频开始持久写入目标 ≤ 2 秒；
- 冷启动、温启动和 App 已在前台都走同一状态机；
- 权限未授予时打开 App 完成说明与授权，不假装已经录音；
- 存在中断会议时提示继续或新建；
- 连续触发不创建并行录音；
- Intent 超时或取消不留下幽灵会议。

### 4.5 后台纪要

真实 60–180 分钟逐字稿至少执行：

1. 前台启动后立即锁屏，完成生成；
2. 生成中切换其他 App ≥ 15 分钟；
3. 在每个主要阶段强制关闭 App，再次启动后继续；
4. 网络断开、恢复；
5. 429/5xx 后自动退避；
6. 密钥失效后修复并继续；
7. 设备重启、未首次解锁时保持暂停，解锁后继续；
8. 生成中开始新录音，生成安全暂停或降级资源，录音不受损；
9. 20 个任务排队，顺序执行且无重复活跃 Job；
10. 用户取消系统 Live Activity 后，状态变为可解释的暂停。

每个场景要求：

- 已完成 Step 不重复；
- 进度恢复且不倒退；
- 最终只有一个当前 `minutes.md`；
- 旧纪要在新结果发布前可读；
- 录音和逐字稿完整；
- 诊断事件足以解释暂停、重试和耗时。

## 5. 性能验收

指标在 Release 构建、真实设备和接近真实数据量下测量。P95 至少基于 30 次样本；长时任务例外时记录完整样本。

### 5.1 启动与交互

| 指标 | 目标 |
| --- | ---: |
| 温启动到首页可交互 | ≤ 1.0 秒 |
| 冷启动到首页可交互 | ≤ 2.0 秒 |
| 首页点击到开始持久录音 | ≤ 1.0 秒 |
| Action Button 冷启动到持久录音 | ≤ 2.0 秒 |
| 2,000 场列表首屏 | ≤ 300 ms |
| 本地全文搜索返回首批结果 | ≤ 500 ms |
| 会议详情基础框架出现 | ≤ 300 ms |
| 音频 seek 后开始播放 | ≤ 300 ms |
| 关键滚动交互 | 无持续可感知卡顿 |

外部 iCloud 文件尚未下载时单独显示下载状态，不把云端等待计入本地渲染指标。

### 5.2 App 侧 AI 开销

为了证明瓶颈不在 App：

- 60 分钟逐字稿的分块规划 P95 ≤ 1 秒；
- 单 Step 检查点事务 P95 ≤ 250 ms；
- 两个模型请求间的 App 编排空隙 P95 ≤ 500 ms，不含明确退避；
- 最终解析、规范化和 Mermaid 源码生成 P95 ≤ 2 秒；
- `minutes.md` 原子发布 P95 ≤ 1 秒，本地可用目录；
- 进度在检查点提交后 1 秒内更新；
- App 可归因开销不超过总生成墙钟时间的 10%，且 60 分钟逐字稿累计不超过 10 秒，取更严格者。

计算：

```text
App 可归因开销
= 总墙钟
- URLSession taskInterval
- 明确的 Retry-After/退避等待
- 系统暂停区间
```

如果 Provider 响应超过两分钟，只要 DNS、连接、TLS、请求发送、首字节、流式持续、解析和落盘均有独立指标，且 App 可归因开销达标，即判定瓶颈不在 App。

### 5.3 数据库与重建

| 指标 | 目标 |
| --- | ---: |
| 2,000 场 metadata 全量扫描 | ≤ 5 秒 |
| 2,000 场索引重建 | ≤ 60 秒，不阻塞录音 |
| FTS 索引更新单场 | ≤ 500 ms |
| 20 个 Job 启动恢复扫描 | ≤ 1 秒 |

## 6. 资源验收

- 3 小时录音期间内存稳定，不随时间线性无界增长；
- 生成每个 Step 完成后释放大响应与中间缓冲；
- 列表和逐字稿使用虚拟化容器；
- WKWebView 按详情生命周期复用或释放，不为每个图永久保留实例；
- 进入后台后无非必要高频 timer；
- 高温或低电量时生成可以变慢或暂停，但录音正确性不下降；
- App 包中的 Mermaid 和依赖体积需要在依赖 PR 中记录。

建议 Release 真机门槛：

- 录音稳定态内存 ≤ 150 MB；
- 2,000 场列表浏览稳定态内存 ≤ 200 MB；
- 单份长纪要详情稳定态内存 ≤ 250 MB；
- 3 小时录音结束后无持续增长趋势。

以上是初始预算；若系统 Framework 本身导致合理超出，需要提供 Instruments 证据并修订文档，而不是静默放宽。

## 7. 隐私与安全验收

- 发布包不包含统计、广告或第三方崩溃上报 SDK；
- 网络抓包只出现系统 iCloud 和用户主动配置的 BYOK 域名；
- BYOK 请求不包含音频、文件 URL 或本地路径；
- API Key 只存在 Keychain；
- Keychain item 使用 AfterFirstUnlockThisDeviceOnly 且不同步；
- 日志与诊断导出不包含 Key、Header、逐字稿、纪要正文或私人路径；
- Mermaid WKWebView 断网可用且拒绝远程导航；
- 所有第三方依赖许可证进入 Settings/Legal 或随包声明；
- Base URL 默认要求 HTTPS；
- 外部链接离开 App 前经过可见的目标确认；
- Privacy Manifest 与实际 API/依赖一致。

诊断包必须通过自动敏感词和结构检查，并进行至少一次人工审计。

## 8. 可访问性与 UI 验收

- VoiceOver 能完整完成开始/结束录音、选择会议、播放录音和继续生成；
- 所有图标按钮有可读 Label；
- 录音、暂停和完成状态不只依赖颜色；
- 支持最大 Accessibility Dynamic Type，不截断关键操作；
- 触控目标至少符合 Apple HIG；
- 深浅色均达到可读对比度；
- Reduce Motion 下没有依赖动画传达的唯一信息；
- Mermaid 提供文字摘要或源码回退；
- 进度同时显示百分比和阶段文字；
- 错误信息提供下一步，不只显示底层错误码；
- 中文排版、英文长单词和长模型名均不会破坏布局。

## 9. 兼容性与恢复

- App 升级后自动迁移数据库；
- Prompt/Schema 版本变化不污染旧 Job；
- Mermaid Runtime 更新后旧图仍可渲染或至少显示源码；
- 模型配置编辑不改变旧 Job；
- 权威目录书签失效时停止写入并请求重新授权；
- 外部移动会议目录后可以重新发现或明确标记缺失；
- App 删除数据库后可重建历史；
- App 删除并重装后，重新授权权威目录即可重建会议内容；API Key 需要重新配置；
- 不承诺自动合并多设备同时编辑同一 Markdown，但不得静默覆盖检测到的外部修改。

## 10. CI 门槛

每个 PR：

- Swift 格式和静态检查通过；
- 所有 Package unit/integration tests 通过；
- Debug 与 Release 编译通过；
- 关键 UI tests 通过；
- migration tests 通过；
- `git diff --check` 通过；
- 新依赖经过依赖治理检查；
- Domain 和 Application 不出现禁止依赖；
- 无密钥、录音或真实逐字稿进入仓库。

合并到主分支：

- 完整 Simulator test matrix；
- 固定 Simulator 的 UI/快照回归；
- Release archive；
- 产物依赖与许可证清单；
- 测试结果和关键性能趋势存档。

真机、长时和真实 Provider 测试可以在发布流水线执行，但不能被普通单元测试替代。

## 11. 缺陷分级

**P0：禁止任何分发**

- 录音、逐字稿或既有纪要不可逆丢失/损坏；
- 密钥或会议正文泄漏；
- 生成任务造成无限计费或重复请求失控；
- 权威目录被错误批量修改。

**P1：禁止 TestFlight 外部内测**

- 后台录音或恢复不可靠；
- Ready 逐字稿无法通过重新生成获得纪要；
- 数据库不能重建；
- Action Button 创建冲突录音；
- 核心流程崩溃；
- 无法查看逐字稿或播放录音。

**P2：允许限期修复后内测**

- 局部布局、非关键图示或次要模型兼容问题；
- 有明确回退的性能问题；
- 不影响数据正确性的诊断缺项。

TestFlight 发布时 P0/P1 必须为 0；P2 必须有已知问题说明和修复计划。
