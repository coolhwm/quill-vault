# MVP 纪要世代与安全替换说明

> 对应实施任务：GitHub Issue #23
> 状态：已实现，待真机验收

## 目标

文字记录就绪后，纪要生成必须始终可恢复。继续生成与重新生成是两个不同的应用用例：继续不改变原任务的文字记录版本或模型快照；重新生成创建新的任务世代并读取当前权威文字记录。

## 任务世代

- 每个会议的任务以 `generationNumber` 单调递增，旧任务记录不会被覆盖。
- 每个任务持久化 `TranscriptRevision` 指纹、模型快照、已完成 Step 和已发布纪要指纹。
- 继续使用任务创建时的模型快照和文字记录版本；编辑当前模型配置不会改变它。
- 重新生成使用当前已选模型，并绑定重新读取的权威 `transcript.md`。
- 同一会议最多一个未完成任务；旧任务的候选结果不能发布到新世代。

## 过期与外部修改

扫描权威目录时，索引保存文字记录版本与纪要 front matter 中的文字记录指纹。两者不一致时，会议状态为“纪要已过期”；旧 `minutes.md` 仍可查看，用户可基于最新文字记录重新生成。

若旧纪要缺少这组来源元数据，索引也按“纪要已过期”保守展示，而不会宣称它已和当前文字记录确认一致；原文件仍保留，用户可以直接重新生成。迁移前已完成的世代没有发布指纹时，工作流会以当前索引中的纪要内容指纹作为一次性基线，后续编辑仍会在生成前和原子发布时复核。

纪要生成任务保存上一次已发布纪要的内容指纹：

1. 重新生成创建任务后，先比较当前 `minutes.md` 与上一次发布指纹。
2. 如果文件被外部编辑，任务立即持久化为 `paused/externalMinutesChanged`，不消耗模型请求，也不修改外部文件。
3. 用户取消确认时，暂停任务和外部版本都保留，可稍后再次确认或继续。
4. 用户确认替换后，继续同一任务世代；发布前再次检查指纹，处理竞态编辑。

确认来自没有活动任务的“纪要已过期”会议时，重新生成会把用户确认时观察到的纪要指纹作为新世代基线；如果之后再次被编辑，仍会暂停并要求重新确认。

## 安全发布

- 模型输出先写同目录候选文件，完成同步、协调、原子替换和读回校验后才标记任务 100% 完成。
- 发布期间在同一个 `NSFileCoordinator` 读写协调块内重新读取并校验 `transcript.md`，再校验 `minutes.md` 指纹，避免源文字记录在校验后被替换。
- 发布失败、取消、进程退出或外部修改不会删除旧 `minutes.md`、`transcript.md` 或 `recording.m4a`。
- 候选临时文件在写入/替换失败路径清理；任务检查点保留可恢复的模型输出。
- MVP 默认不删除原始录音。未来若增加用户设置，也只能在文字记录和纪要均确认发布后执行删除。
- 被新世代替代的旧后台任务即使已经提交到系统队列，也会因持久化任务状态不再活动而自失效；系统回调不会为旧世代读取或发布结果。

## 用户反馈

- 生成中显示阶段、百分比、分段进度和取消操作。
- 纪要过期或外部纪要发生变化时显示原因及重新生成/替换确认。
- 失败任务保持可继续；生成完成后仍提供重新生成入口。

## 自动化覆盖

- Core：新世代使用当前模型、外部纪要变更在模型请求前暂停、确认后沿用任务恢复并替换。
- Infrastructure：任务世代与发布指纹跨数据库重启保存；索引区分已完成与已过期纪要；文件存储可读取发布指纹。
- 真机仍需验证：外部编辑 `minutes.md` 后取消/确认、强杀后恢复、后台生成及大文本生成。
